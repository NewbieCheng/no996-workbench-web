# 视频导出兼容与人工验收

## 当前实现目标

网页端新导出的交付目标为 MP4 容器、H.264 视频；存在音轨时要求 AAC 音频。WebM/VP9 不作为静默替代格式。文件扩展名和 Blob MIME 只能作为线索，不能单独证明实际编码，也不能代替微信播放验收。

视频工厂与 IP 编排共用浏览器任务导出入口。快速导出通过预览舞台录制，精确导出逐帧编码；两者都在本机浏览器执行，页面关闭或刷新会中断。浏览器 WebCodecs 的能力预检与实际 H.264 编码使用 `hardwareAcceleration: 'no-preference'`，不强制依赖浏览器可用的硬件编码器。快速录制的 MediaRecorder 后备只接受其声明支持的 MP4/H.264 类型；含音轨时要求声明支持 AAC。

数字人多段拼接也只请求 MP4 MediaRecorder。单段直返要求 Blob MIME 明确为 `video/mp4`；未确认的源格式会失败并提示重新生成 MP4，而不是把任意源文件改名为 MP4。该限制不等同于完成了转码。

## Edge 与 Chrome 手动测试

由产品/用户在真实浏览器完成，工程代码修改和静态检查不代表真实浏览器或微信已验收。

1. 使用之前出现问题的 Edge 打开同一个视频工厂工程，先执行快速导出，再执行精确导出。记录每条路径是否成功、等待时间、选定分辨率，以及是否出现降级或失败提示。
2. 若失败，在任务中心打开对应失败任务，点击「复制错误详情」，把文本粘贴给开发者。日志应包含浏览器版本、模块、导出方式、输出尺寸、帧率、目标码率、音轨状态、失败阶段和浏览器错误；日志不应包含工程名称、素材内容、凭据或 URL。
3. 在同一台机器的 Chrome 对相同工程、分辨率、快速/精确方式重复测试，记录差异。不要为了测试先改变工程内容或素材。
4. 对有声成片检查画面、字幕、音频是否完整，开头/结尾是否缺帧，音画是否同步，文件能否重新打开。再尝试 720p、1080p、横屏和竖屏；任何自动改变分辨率都应有明确提示并由用户确认。
5. 分别核对视频工厂、IP 视频的导出入口；数字人测试单段原文件和多段合并。格式不符合目标时应明确失败，不能把 WebM 或未知 MIME 文件伪装成 `.mp4`。
6. 将代表性 MP4 发至微信，分别在实际可用的微信桌面端和手机微信中播放，记录系统、设备、微信版本及结果。未实际测试的设备/版本标记为未验收。
7. 如需检查内部格式，使用可信媒体信息工具确认容器、视频编码、音频编码、尺寸和时长。不要只依据文件名、扩展名或下载成功提示判断。

## 失败排查

Edge 与 Chrome 对相同导出配置行为不同，可能来自浏览器版本、操作系统媒体栈、编码器实现或浏览器图形加速/驱动状态；仅凭错误提示不能认定某一因素。用户可尝试更新 Edge、检查图形加速设置并重启后复测，但产品运行不应以用户修改浏览器设置为前提。通过「复制错误详情」回传具体失败阶段和浏览器错误，便于继续定位。

当前不会自动上传诊断信息；复制是用户主动操作。浏览器/微信真实验收结果由用户补充，未测试的组合不得宣称已兼容。
