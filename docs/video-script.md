# 视频脚本（script-lab）模块说明

- 页面：`/workbench/video-script`（视频）与 `/workbench/live-script`（直播），共用 `ScriptLabPage` + 同一套 Agent flow
- 代码：`src/features/script-lab/`、流程内核 `src/agent/`
- 相关计划与复盘：[video-script-four-purpose-plan.md](video-script-four-purpose-plan.md)

## 1. 创作目的（2026-10-28 起）

视频脚本先选创作目的，再选该目的下的叙事结构。目的与结构都由用户显式选择，模型只展开、不选择。

| 目的 | 结构（各 5 段，占比由宿主锁定） |
|---|---|
| 获客型 | 人群点名型 / 问题诊断型 / 结果前置型 / 场景急救型 |
| 人设型 | 经历转折型 / 选择与原则型 / 工作幕后型 / 踩坑复盘型 |
| 观点·干货型 | 反常识论证型 / 步骤教学型 / 错误与正确对照型 / 问题拆解型 |
| 转化型 | 痛点解决型（PAS）/ 交付演示型 / 疑虑答疑型 / 价值递进型（AIDA） |

数据资产在 `src/features/script-lab/agent/purposes/`（方法块、评审口径、结构、必填素材）。修改方法或结构只改这里，页面/提示词/预览会自动跟着变。

## 2. 生成流程（8 阶段）

预填 → 策划 → 结构 → 编剧 → 硬校验 → 评审 → 编辑（≤3 轮）→ 定稿。

- **结构**：候选就是用户选定的那一套；宿主锁定段名、顺序、占比，模型只补每段 `purpose`。
- **输入锁定**：产品名 100% 来自用户输入；用户已填的人群/痛点/卖点也由宿主锁定，策划只补空。策划返回「产品/人群/痛点/卖点」这类占位词时一律丢弃（2026-10-29 修复）。
- **编剧**：注入该目的的方法块 + 本次素材（第一行就是产品/主题，缺失的必填项显式写「缺失，不能编造」）+ 字数预算。直播与视频都注入产品介绍、素材、参考脚本和附件。
- **硬校验**：违禁词按段展开命中；「第一」有序数白名单与宣称语境；字数按「口播字数」（去空白与标点）判定；只要填了产品/主题，视频和直播都会检查「全文是否提到本次主体」（完整名或关键片段），完全没提判为跑题。
- **评审**：拿到本次产品/主题、素材摘要、`mustFixIds` 与逐段命中；写成别的产品/人设业务必须标 mustFix。评审不继承人设背景，保持独立。
- **编辑**：拿到字数总账（目标区间 / 当前 / 差额 / 逐段预算），只允许改 targetIds。
- **定稿**：**硬校验没过也交付**，`pass=false` + `stopReason` 写明待修改项；任务算成功但带「有 N 处待修改」提示。不再整份丢弃。

## 3. 输入与限额

- 视频任务的必填：产品/主题、创作目的、叙事结构，以及该目的的必填素材。缺项时停在向导里、不调模型。
- 参考资料：txt / md / docx；单份正文 ≤ 5 万字（超出拒绝），单次合计 ≤ 8 万字（超出截断并在正文标注）。
- 人设预填只补「人群 / 痛点」；产品介绍与卖点不再从人设自动填，避免换产品后仍在讲人设的主营业务。
- 生成预算：预填 8192 token；编剧/编辑 8192；评审 8192；截断重试上限 32768（与后端 `max_tokens_cap` 一致）。
- 成稿出现后输入向导自动收起，页面只保留过程与成稿；需要改设置时用页头「展开输入配置」恢复。

## 4. 历史兼容

- 旧 `流量` 任务原样展示；继续生成时要求重选目的（不暗中归类）。
- 旧 `成交` 任务生成时按转化型处理，界面明示映射。
- 旧结构名、旧结果与 Markdown 字段不迁移、不改写。

## 5. 质量闸

- 纯逻辑单测：`hard-check`、`purposes`、`purpose-readiness`、`library`、`structure-plan`、`retention`。
- 离线端到端：`npm run test:flows`（含「硬校验未解除仍交付」「5 段结构锁定 + 目的方法注入」）。
